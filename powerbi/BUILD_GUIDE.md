# Power BI build guide (for a complete beginner)

You will turn the CSVs in `data/processed/` into a 4-page report. Everything is prepared; your job is to
load, connect, paste and arrange. Read `DATA_MODEL.md` and `REPORT_SPEC.md` once before you start.

**Honest time estimate for a first-timer: about 5 to 7 hours**, best split over two sessions.

| part | what | time |
|---|---|---|
| 1 | Install Power BI Desktop | 15–30 min |
| 2 | Load the CSVs and check data types | 30–45 min |
| 3 | Date table, sort orders, relationships | 30 min |
| 4 | Paste the measures and check them against the expected values | 45–60 min |
| 5 | Theme and page 1 | 60 min |
| 6 | Pages 2–4 | 2–3 h |
| 7 | Test with filters, export PDF, screenshots | 30 min |

---

## 1. Install Power BI Desktop (15–30 min)

* Power BI Desktop is **Windows only**. Install it free from the **Microsoft Store** (search "Power BI
  Desktop"); the Store version updates itself. No account is needed to build and save a `.pbix` file.
* **Mac or no Windows?** Power BI **Service** in a browser (app.powerbi.com) can create a report from an
  uploaded CSV or Excel file, but it needs a work or school account, has no Power Query editor like Desktop,
  and model editing is limited. Building this kit there is possible but slower; a Windows machine (or a
  Windows virtual machine) is the realistic route.

## 2. Load the CSVs (30–45 min)

1. Open Power BI Desktop → **Blank report**.
2. First, stop Power BI guessing relationships for you: **File → Options and settings → Options →
   Current file → Data load** → untick **Autodetect new relationships after data is loaded** → OK.
3. **Home → Get data → Text/CSV** → pick `data/processed/dim_building.csv` → in the preview check that the
   **File origin** is *65001: Unicode (UTF-8)* and the delimiter is *Comma* → **Transform Data**.
4. In the Power Query editor, look at the icon left of each column name (ABC = text, 1.2 = decimal,
   123 = whole number, calendar = date, ✓✗ = true/false). Compare with the table in `DATA_MODEL.md` →
   *Data types to check*. Fix a wrong one by clicking the icon. Dates must be **Date**, not Date/Time
   (except the two `timestamp` columns).
5. **Home → New Source → Text/CSV** for each remaining file:
   `dim_date`, `fact_daily_energy`, `fact_hourly_energy`, `fact_monthly_kpi`, `fact_annual_kpi`,
   `fact_anomalies`, `fact_opportunities`, `assumptions`, `data_quality_report`.
6. **Home → Close & Apply.** Loading `fact_hourly_energy` (219,000 rows) takes a few seconds.

If numbers arrive as text, or 0.675 turns into 675, your Windows region uses a comma decimal. Fix it with
the queries in `power_query.m` (they force the "en-US" culture), or set **File → Options → Current file →
Regional settings → Locale for import** to *English (United States)* and reload.

## 3. Date table, sort orders, relationships (30 min)

**Mark the date table**
1. Left bar → **Table view** → select `dim_date`.
2. **Table tools → Mark as date table** → choose column `date` → OK.

**Sort text columns properly** (otherwise Apr comes before Jan and Fri before Mon)
1. In `dim_date` click `month_name` → **Column tools → Sort by column → month**.
2. Click `day_name` → **Sort by column → day_of_week**.

**Create the relationships**
1. Left bar → **Model view**. You will see the 10 tables as boxes.
2. Drag `building_id` from `dim_building` onto `building_id` in each of the 6 fact tables
   (see the list in `DATA_MODEL.md`). In the dialog check: Cardinality **One to many (1:\*)**,
   Cross filter direction **Single**, **Make this relationship active** ticked → OK.
3. Drag `date` from `dim_date` onto `date` in `fact_daily_energy`, `fact_hourly_energy`, `fact_anomalies`,
   and onto `month_start` in `fact_monthly_kpi`.
4. Leave `assumptions` and `data_quality_report` **unconnected**.
5. Hide the columns listed in `DATA_MODEL.md` → *Columns to hide* (right-click → **Hide in report view**).

## 4. Measures (45–60 min)

1. **Home → Enter data** → name the table `_Measures` → **Load**.
2. Select `_Measures` in the Data pane → **Table tools → New measure**.
3. From `measures.dax`, copy ONE measure (from its name down to the line before the next `//` comment),
   paste it into the formula bar, press **Enter**. Repeat for all.
4. Formats (select the measure → **Measure tools**): percentages for the `%` measures; 0 decimals for kWh,
   INR and counts; 1 decimal for EUI; 3 decimals for Load Factor.
5. Once at least one measure works, the empty column in `_Measures` can be hidden.

## 5. Theme and page 1 (60 min)

1. **View → Themes → Browse for themes** → pick `powerbi/theme.json`.
2. **View → Page view → Fit to page**; Format pane (paintbrush) with nothing selected → **Canvas settings**
   → 16:9.
3. Build **Page 1: Portfolio Overview** from `REPORT_SPEC.md`. For each visual: click the visual type in
   the **Visualizations** pane, then drag fields from the **Data** pane into the wells
   (X-axis, Y-axis, Legend, Values) exactly as the spec lists.
4. Card titles: select the card → Format → **General → Title** → write the title from the spec.
5. Subtitle on the page: add a **Card** with the `[Report Subtitle]` measure (Format → Callout value →
   font size 9, and turn off the category label), stretched across the top.
6. Rename the page (double-click the tab at the bottom).

## 6. Pages 2–4 (2–3 h)

Follow `REPORT_SPEC.md` page by page. Three things that are new on these pages:

* **Single-select slicer** (page 2): select the slicer → Format → **Slicer settings → Selection → Single
  select** on.
* **Anomaly markers on a line** (page 2): add `[Total kWh]` and `[kWh on Anomaly Days]` to the same line
  chart's Y-axis. Format → **Lines** → series *kWh on Anomaly Days* → width 0; **Markers** → on, that series
  only, red `#d03b3b`, size 6.
* **Heatmap matrix** (page 2): Matrix visual → Rows `day_name`, Columns `hour`, Values `[Avg kWh per Hour]`.
  Format → **Cell elements → Background colour → fx** → Format style *Gradient*, lowest `#cde2fb`, highest
  `#184f95`. Turn row and column subtotals off.
* **Sync slicers** (optional): View → **Sync slicers** to make the building-type slicer apply on every page.

## 7. Test, export, screenshot (30 min)

* **Filter test:** pick one building on page 2. `EUI (annual)` must equal that building's
  `eui_kwh_m2` in `fact_annual_kpi`, and the rank must match `eui_rank_in_type`. Clear the slicer and the
  page-1 cards must return to the expected values above.
* **Cross-filter test:** click a bar on page 1; other visuals should filter. If a visual does not react,
  its table is not related (check Model view).
* **Export to PDF:** File → **Export → Export to PDF**.
* **Publish (optional):** Home → **Publish** needs a Power BI account (work or school email). Without one,
  take screenshots of each page (Windows: Win + Shift + S) and save them to `reports/powerbi_screens/`.

## You're done when

- [ ] All 10 tables load with the types in `DATA_MODEL.md` and no Error cells
- [ ] `dim_date` is marked as the date table; month and day names sort correctly
- [ ] 10 relationships exist, all one-to-many and single direction; `assumptions` and
      `data_quality_report` are unconnected
- [ ] Every measure in `measures.dax` is created and the test table matches the expected values
- [ ] 4 pages exist as in `REPORT_SPEC.md`, each with the `[Report Subtitle]` card
- [ ] Slicers filter as expected (filter test and cross-filter test pass)
- [ ] The report is saved as `powerbi/retail_energy_report.pbix`, exported as PDF, and screenshots are in
      `reports/powerbi_screens/`
- [ ] **Only then:** change the README status line to `Power BI report: BUILT by JP in Power BI Desktop
      (date)`

## Common errors

| symptom | cause | fix |
|---|---|---|
| A column of numbers shows as text (ABC) or sums wrongly | type detection or comma-decimal locale | Fix the type in Power Query, or use `power_query.m` (en-US culture) |
| Dates are Date/Time and the date slicer shows times | type not set to Date | Set `date` and `month_start` to **Date** in Power Query |
| Visual shows the same number on every row | relationship missing or inactive | Model view: check the dimension → fact line exists and is solid (active) |
| "There's ambiguity in the relationship paths" / dashed line | two paths between the same tables, or a Both-direction filter | Keep every relationship **Single** direction; do not relate fact tables to each other |
| A measure shows blank | a filter removed all rows, or `HASONEVALUE` needs exactly one building | Select one building for the rank/percentile measures; check slicers |
| Error "The syntax for … is incorrect" | measure pasted with the `//` comment line or two measures at once | Paste one measure: name line + formula only |
| `CO2 Factor t per MWh` errors | `assumptions[value]` text "0.675" not converted in a comma-decimal locale | Set the import locale to English (United States), or replace the measure with the number 0.675 and note it |
| Month names sorted alphabetically | Sort by column not set | `month_name` → Sort by column → `month` |
| Totals look too big on the opportunities page | overlapping opportunity types added | Use the `Estimated Savings` measures (headline only) or select one type and one scenario |
| A date slicer does not change EUI or opportunities | intended: they are whole-year figures | Say "full year" in those visuals' titles |
